## 🧩 آنچه امروز به تو داده شده

### فایل `index.html` — پروتوتایپ ۵ صفحه‌ای

یک تک‌فایل HTML با **۶۷۰ خط**، بدون build، بدون وابستگی. پنج صفحه دارد:

| # | صفحه | چه می‌کند |
|:---:|------|-----------|
| ۱ | مشتری و میز | انتخاب مشتری از فهرست یا ساخت مشتری با شماره، انتخاب نوع سفارش (سالن/بیرون‌بر/پیک)، انتخاب میز از ۸ میز |
| ۲ | منو | ۶ دسته، ۱۲ آیتم با **رسپی**، سبد کنار صفحه، **موجودی قابل فروش** روی هر کارت |
| ۳ | کسر مواد | جدول «لازم / موجودی / پس از کسر» با رنگ هشدار |
| ۴ | پرداخت | نقد / کارتخوان / ترکیبی، محاسبهٔ خودکار باقی‌مانده |
| ۵ | فیش | دو رسید کنار هم: **رسید مشتری ۸۰mm** و **فیش آشپزخانه بدون مبالغ** |

### ✅ این پروتوتایپ چه چیزی را **اثبات** می‌کند

1. **فروش = انفجار رسپی.** لحظهٔ تأیید سفارش، مواد کسر می‌شود — نه در پرداخت. این `Δ-01` است و مهم‌ترین قاعدهٔ محصول.
2. **موجودی باید در لحظهٔ فروش دیده شود.** هر کارت منو «۴۰ عدد» نشان می‌دهد.
3. **دو چاپگر با دو رسانهٔ متفاوت** — رسید با مبلغ (`FR-PAY-07`) و فیش آشپزخانه **بدون مبلغ** (`FR-ORD-11`).
4. **شمارهٔ سفارش بزرگ و خوانا** — مشتری با همین شماره صدا زده می‌شود.
5. **زبان بصری** — RTL، فونت Tahoma، رنگ نارنجی `#e8590c`، کارت‌های ۱۶px، دکمه‌های ۱۲px.

### 🎨 زبان بصری که باید **حفظ** شود

```css
--bg:#eef0f4;  --card:#fff;   --line:#e3e7ef;  --txt:#16202e;  --mut:#8b94a5;
--acc:#e8590c; --acc-soft:#fff1e6;
--ok:#188a4d;  --ok-soft:#e8f7ee;
--warn:#b45309;--warn-soft:#fef3c7;  --red:#dc2626;
```
- فونت: `Tahoma, "Segoe UI", Arial, sans-serif` — **فونت آنلاین بارگذاری نکن** (اینترنت رستوران قطع می‌شود)
- جهت: `dir="rtl"` · `lang="fa"`
- شعاع: کارت `16px` · دکمه `12px` · چیپ `99px`
- اعداد: **فارسی** با جداکنندهٔ `٬` — تابع `nf()` و `fa()` در پروتوتایپ درست است، نگهش دار
- ارقام جدولی: `font-variant-numeric: tabular-nums`
- کارت‌ها با حاشیهٔ ۱px و سایهٔ بسیار ملایم — نه glassmorphism، نه گرادیان
- **اصل طراحی: صندوق‌دار با یک دست و در ۳ ثانیه باید بتواند کار کند.** دکمه‌ها بزرگ، فاصله‌ها راحت

| سرور | **Node + Fastify** یا **NestJS** | Fastify سبک‌تر برای تک‌نفره؛ Nest ساختارمندتر برای ۳۶ موجودیت |
| ORM | **Prisma** یا **Drizzle** | Prisma بالغ‌تر؛ Drizzle سبک‌تر و SQL-first (اگر بعداً SQLite محلی بیاید بهتر) |
| دیتابیس | **PostgreSQL** | `Δ-37` احتمالاً SQLite محلی هم اضافه می‌کند — ORM باید هر دو را بدهد |
| اعتبارسنجی | **Zod** | یک schema برای فرم، API و type |

> 🔴 **هر انتخاب را با هزینه‌اش بگو، نه فقط مزیتش.** کاربر تصمیم‌گیر نهایی است (`Δ-01`).

### 🔌 طراحی برای آفلاین — حتی اگر الان نسازی

`Δ-37` در حال بازبینی است و ممکن است معماری آفلاین را از «کش مرورگر» به **سرور محلی + SQLite + Outbox** تغییر دهد. پس:

| ✅ بکن | ❌ نکن |
|--------|-------|
| **همهٔ** نوشتن‌ها را از یک لایهٔ `posClient` رد کن | در کامپوننت مستقیم `fetch` بزن |
| هر عملیات نوشتن یک **`event_id` (UUID)** بساز | سرور را بر اساس ترتیب فرضی پیام‌ها طراحی کن |
| API سرور را **idempotent** طراحی کن: UNIQUE روی `event_id` | فرض کن درخواست دو بار نمی‌رسد |
| منطق مالی را در یک ماژول **خالص و تست‌پذیر** جدا کن | منطق پول را در کامپوننت React بنویس |
| مبالغ را **عدد صحیح ریال** نگه دار (نه float) | `0.1 + 0.2` |
| قیمت، مالیات و تخفیف را در لحظهٔ فروش **Snapshot** کن | قیمت را از جدول `product` بخوان در لحظهٔ گزارش |
| قالب تاریخ و اعداد را در یک ماژول متمرکز کن | `new Date()` پراکنده در کل کد |
